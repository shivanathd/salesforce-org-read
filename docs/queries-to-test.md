# Queries to test before merge

These queries were added for the v0.2 skills and for review fixes. They use only fields listed in Salesforce's Object Reference or Tooling API reference. Most were run on a Developer Edition scratch org on 2026-10-18 (QA of commit f983a84; the changed `object-code` and `field-descriptions` queries were run again after the fix); the Result column says what came back. Run any query with no Result on a scratch org (with some Apex, flows, a custom object and a validation rule) before relying on it, and note the result here.

Until a query has a Result here, the skills treat 0 rows from it as **unassessed**, not as zero: an empty result may mean the query or its filter does not work as written.

The script prints a marker line before each query's JSON: `### <check> <n>/<total>: <label>`.

Run a check with `bash scripts/org-read-cli.sh <alias> <check> [object]`, or a single query with `sf data query --target-org <alias> --json [--use-tooling-api] --query "<query>"`.

Also test the script itself:
- `bash scripts/org-read-cli.sh <alias> object "Account' OR"` must exit 2 without running a query.
- Each query's JSON follows a `### <check> <n>/<total>: <label>` line, and `<total>` equals the number of queries that check registers in `scripts/org-read-cli.sh` (the table above lists only the queries added since the first release).
- A check where every query fails (for example an alias that is not logged in) exits 4 and says so on stderr; a check where only some fail exits 0.
- The alias must match `^[A-Za-z0-9_.@][A-Za-z0-9_.@-]{0,79}$`: `myorg` and `me@example.com` run, `-x`, `a;b` and an 81-character alias exit 2. An object name over 80 characters exits 2.
