# Queries to test before merge

These queries were added for the v0.2 skills and for review fixes. They use only fields listed in Salesforce's Object Reference or Tooling API reference, but none has been run against an org yet. Run each one on a scratch org (with some Apex, flows, a custom object and a validation rule) before merging, and note the result here.

Until a query has a Result here, the skills treat 0 rows from it as **unassessed**, not as zero: an empty result may mean the query or its filter does not work as written.

The script prints a marker line before each query's JSON: `### <check> <n>/<total>: <label>`.

Run a check with `bash scripts/org-read-cli.sh <alias> <check> [object]`, or a single query with `sf data query --target-org <alias> --json [--use-tooling-api] --query "<query>"`.

| Check | Query | API | What to expect | Result |
| --- | --- | --- | --- | --- |
| `org` | `SELECT NamespacePrefix FROM Organization` | Standard | One row; null for most orgs. Test on an org with its own namespace too, if one is at hand. | |
| `whoami` | `SELECT PermissionsModifyAllData, PermissionsAuthorApex, PermissionsCustomizeApplication, PermissionsManageUsers, PermissionsViewSetup, PermissionsViewAllUsers FROM UserPermissionAccess` | Standard | One row of booleans for the signed-in user, no name or email. Test as an admin (write permissions true) and as a Read Only user (false). If it fails, the skill says it could not check the login and still recommends a read-only user. | |
| `licences` | `SELECT Profile.UserLicense.Name, COUNT(Id) FROM User WHERE IsActive = true GROUP BY Profile.UserLicense.Name` | Standard | Active users this login can see, by licence. Same shape as the tested 90-day query. Compare with `UserLicense.UsedLicenses`, as an admin and as a user without View All Users. | |
| `admins` | `SELECT AssigneeId FROM PermissionSetAssignment WHERE PermissionSet.PermissionsModifyAllData = true AND Assignee.IsActive = true GROUP BY AssigneeId LIMIT 2000` | Standard | One row per distinct active user with Modify All Data. Check that users who get it only from their profile are included (their profile is a profile-owned permission set with an assignment); compare with the tested profile count in the same check. | |
| `triggers` | `SELECT Name, TableEnumOrId, ApiVersion, Status FROM ApexTrigger WHERE NamespacePrefix = null AND Status = 'Active' ORDER BY TableEnumOrId LIMIT 200` | Tooling | Your active triggers only. The query without `Status = 'Active'` was tested; check that an inactive trigger is now left out. | |
| `triggers` | `SELECT ApiName, NamespacePrefix, TriggerType, TriggerOrder, TriggerObjectOrEventId, TriggerObjectOrEvent.QualifiedApiName FROM FlowDefinitionView WHERE TriggerType IN ('RecordBeforeSave', 'RecordAfterSave', 'RecordBeforeDelete') AND IsActive = true AND NamespacePrefix = null LIMIT 200` | Standard | Your active record-triggered flows with the object's Id and API name. Check that an inactive flow and a managed-package flow are left out, and that `TriggerObjectOrEventId` equals the trigger query's `TableEnumOrId` for a custom object (both an Id) and for a standard object. | |
| `flows` | `SELECT ApiName, NamespacePrefix, Label, ProcessType, TriggerType, TriggerObjectOrEventLabel, TriggerOrder, IsActive, IsOutOfDate, ApiVersion, LastModifiedDate FROM FlowDefinitionView WHERE NamespacePrefix = null ORDER BY LastModifiedDate DESC LIMIT 200` | Standard | The tested `flows` query plus `NamespacePrefix` and a filter to your own flows. Check that a managed-package flow is left out. | |
| `flows` | `SELECT ApiName, NamespacePrefix FROM FlowDefinitionView WHERE NamespacePrefix != null LIMIT 200` | Standard | Managed-package flows only, so the note can say how many were left out. Check whether their `ApiName` also carries the prefix. | |
| `tests` | `SELECT COUNT(Id) FROM ApexClass WHERE NamespacePrefix = null` | Standard | One count of your own Apex classes; 0 means Tests scores Finish ("no Apex to test"). | |
| `tests` | `SELECT AsyncApexJobId, IsAllTests, ClassesEnqueued, Source FROM ApexTestRunResult ORDER BY StartTime DESC LIMIT 5` | Standard | The same 5 runs as the first `tests` query, with `IsAllTests` true for a run of all tests. Run all tests once and one test class once, and check the two runs differ. If the query fails, the skill cannot tell full runs from partial ones and lowers confidence. | |
| `permissions` | `SELECT COUNT(Id) FROM PermissionSet WHERE IsOwnedByProfile = false AND IsCustom = true AND NamespacePrefix = null` | Standard | One count of your own custom permission sets, without standard and managed-package ones. The earlier unfiltered count was tested. | |
| `renewal` | `SELECT Profile.UserLicense.Name, COUNT(Id) FROM User WHERE IsActive = true AND (LastLoginDate < LAST_N_DAYS:60 OR LastLoginDate = null) GROUP BY Profile.UserLicense.Name` | Standard | One row per licence with a count. Same shape as the 90-day query in `licences`, which is tested. | |
| `recent-changes` | `SELECT LastModifiedBy.Name, COUNT(Id) FROM ApexClass WHERE NamespacePrefix = null AND LastModifiedDate = LAST_N_DAYS:90 GROUP BY LastModifiedBy.Name` | Standard | One row per person with a count of classes they last saved in 90 days. | |
| `recent-changes` | `SELECT LastModifiedBy.Name, COUNT(Id) FROM ApexTrigger WHERE NamespacePrefix = null AND LastModifiedDate = LAST_N_DAYS:90 GROUP BY LastModifiedBy.Name` | Standard | As above, for triggers. | |
| `recent-changes` | `SELECT ApiName, NamespacePrefix, LastModifiedBy, LastModifiedDate FROM FlowDefinitionView WHERE NamespacePrefix = null AND LastModifiedDate = LAST_N_DAYS:90 ORDER BY LastModifiedDate DESC LIMIT 200` | Standard | Your own flows changed in 90 days (managed-package flows left out); `LastModifiedBy` is a text name on this view. `LastModifiedDate` is already used (in ORDER BY) by the tested `flows` query, but filtering on it is new. | |
| `flow-descriptions` | `SELECT ApiName, NamespacePrefix, ProcessType, IsActive FROM FlowDefinitionView WHERE NamespacePrefix = null AND Description = null ORDER BY ApiName LIMIT 200` | Standard | Your own flows with an empty description (`Description` is documented as filterable). Check that a managed-package flow is left out. | |
| `class-coverage` | `SELECT ApexClassOrTriggerId, NumLinesCovered, NumLinesUncovered FROM ApexCodeCoverageAggregate LIMIT 500` | Tooling | One row per class or trigger that has coverage from a test run. Needs View Setup and Configuration. Empty if no tests have run. | |
| `class-coverage` | `SELECT Id, Name FROM ApexClass WHERE NamespacePrefix = null ORDER BY Name LIMIT 500` | Standard | Class Ids and names, to match the coverage rows. | |
| `class-coverage` | `SELECT Id, Name FROM ApexTrigger WHERE NamespacePrefix = null ORDER BY Name LIMIT 500` | Standard | Trigger Ids and names. | |
| `api-45` | `SELECT Name, ApiVersion FROM ApexClass WHERE NamespacePrefix = null AND ApiVersion < 45 ORDER BY ApiVersion LIMIT 200` | Tooling | Same shape as the tested `old-code` query, with `< 45`. | |
| `api-45` | `SELECT Name, ApiVersion FROM ApexTrigger WHERE NamespacePrefix = null AND ApiVersion < 45 ORDER BY ApiVersion LIMIT 200` | Tooling | As above, for triggers. | |
| `fields` | `SELECT TableEnumOrId, COUNT(Id) FROM CustomField WHERE NamespacePrefix = null GROUP BY TableEnumOrId LIMIT 200` | Tooling | One row per object with its custom field count; custom objects appear as Ids. `TableEnumOrId` is documented as groupable, but whether Tooling accepts this aggregate is the main thing to test. If it fails, fall back to `SELECT TableEnumOrId FROM CustomField WHERE NamespacePrefix = null LIMIT 2000` and count. | |
| `fields` | `SELECT Id, DeveloperName FROM CustomObject WHERE NamespacePrefix = null ORDER BY DeveloperName LIMIT 500` | Tooling | Custom object Ids and names (without `__c`), to map the Ids above. | |
| `inventory` | `SELECT COUNT(Id) FROM ApexClass WHERE NamespacePrefix = null` | Standard | One count. | |
| `inventory` | `SELECT COUNT(Id) FROM ApexTrigger WHERE NamespacePrefix = null` | Standard | One count. | |
| `inventory` | `SELECT COUNT(Id) FROM CustomObject WHERE NamespacePrefix = null` | Tooling | One count. CustomObject is not on Salesforce's list of Tooling objects without COUNT, but test it. | |
| `object` | `SELECT DurableId, QualifiedApiName FROM EntityDefinition WHERE QualifiedApiName = 'Account'` (and a custom object) | Tooling | One row. `DurableId` should be the name for a standard object and an Id (`01I…`) for a custom object. No LIMIT: EntityDefinition ignores it. | |
| `object` | `SELECT ValidationName, Active FROM ValidationRule WHERE EntityDefinition.QualifiedApiName = 'Account' LIMIT 200` | Tooling | One row per validation rule on the object. | |
| `object` | `SELECT ApiName, NamespacePrefix, ProcessType, TriggerType, RecordTriggerType, TriggerOrder, IsActive FROM FlowDefinitionView WHERE TriggerObjectOrEvent.QualifiedApiName = 'Account' LIMIT 200` | Standard | Flows triggered by the object. `TriggerObjectOrEvent` is a documented lookup to EntityDefinition; filtering through it on this view is untested. If it fails, filter on `TriggerObjectOrEventId` = the object's `DurableId` instead. If that also fails, mark the object's flows unassessed; never match by `TriggerObjectOrEventLabel`. | |
| `object-code` | `SELECT Name, ApiVersion, Status FROM ApexTrigger WHERE TableEnumOrId = '<DurableId>' LIMIT 200` | Tooling | Triggers on the object. Test with a standard object (name) and a custom object (Id from the `object` check). For a custom object, `DurableId` is a 15-character Id; check that it matches `TableEnumOrId`, and also try the 18-character form of the same Id. Note which form returns the trigger. | |
| `object-code` | `SELECT Id, Name FROM WorkflowRule WHERE TableEnumOrId = '<DurableId>' LIMIT 200` | Tooling | Workflow Rules on the object. Same two cases. | |
| `field-descriptions` | `SELECT QualifiedApiName, Description FROM FieldDefinition WHERE EntityDefinition.QualifiedApiName = 'Account' AND NamespacePrefix = null` | Tooling | One row per field on the object that is not from a package, with its description or null. No LIMIT: FieldDefinition ignores it and needs an object filter. Check that a managed-package field is left out. If `NamespacePrefix` is not filterable here, drop the filter; the skill already counts only fields ending in `__c` with no other `__`. | |

Also test the script itself:
- `bash scripts/org-read-cli.sh <alias> object "Account' OR"` must exit 2 without running a query.
- Each query's JSON follows a `### <check> <n>/<total>: <label>` line, and the totals match the rows above.
- A check where every query fails (for example an alias that is not logged in) exits 4 and says so on stderr; a check where only some fail exits 0.
